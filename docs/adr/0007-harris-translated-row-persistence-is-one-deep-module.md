# Harris translated-row persistence is one deep module

All Harris Property, Building, and Extra Feature translated rows cross `HarrisPersistence.persist(PersistenceRequest)` in `counties/harris/etl_pipeline/persistence.py`. The immutable request names one domain dataset, supplies a one-pass row stream, and makes Replace or Add Missing intent explicit. The immutable result reports the dataset, write mode, loaded, invalid, and skipped counts, one batch identifier, and any logically invalidated dependent datasets. Callers do not select a table, model, concrete adapter, or backend-specific option.

`persistence_for_connection()` selects the streaming PostgreSQL COPY adapter or the bounded Django ORM adapter. Both implement the same ordered-schema, complete-identity, duplicate, metadata, replacement, and result contract. A Property replacement invalidates Building and Extra Feature and lets database cascades remove their rows. An empty, all-invalid, or all-skipped replacement raises `UnsafeReplacementError` and rolls back. Add Missing never updates an existing row. COPY failures never retry through ORM, and database failures retain their original context after the persistence module logs the dataset.

Each call owns one transaction for one logical dataset. Several physical Extra Feature sources are chained into one call. Earlier dataset commits remain when a later dataset fails, and the supported operational model is one authoritative writer; constraints protect integrity under accidental concurrency, but exact skipped counts are not promised for competing writers. The COPY adapter retains one-pass streaming and set-based insertion, while the ORM adapter retains bounded batching. Stable generated identifiers, model hooks, and identical backend mechanics are not guarantees.

The higher-level Harris import remains responsible for catalog selection, acquisition, extraction, translation order, account-map rebuilding after Property replacement, readiness, plan-aware completeness, cleanup, result classification, and compatibility at management-command and Celery boundaries. GIS updates, fixture-derived room-count updates, readiness refresh, assessment history, and jurisdiction imports do not cross this seam. The module also does not provide generalized upserts, cross-dataset atomicity, or concurrent-writer coordination.

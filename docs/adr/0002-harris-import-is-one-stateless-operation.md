# Harris import is one stateless operation

All authoritative Harris imports cross `run_harris_import(HarrisImportRequest)` and let that module own HCAD catalog selection, acquisition and extraction reuse, translated-row loading or preview, strict or best-effort stopping, readiness refresh, plan-aware completeness validation, cleanup eligibility, and result classification. Management commands and Celery tasks remain compatibility adapters for their existing flags, task names, progress states, and serialized result dictionary; download-only, extract-only, cleanup-only, status, and targeted recovery operations continue to use their focused modules directly.

The request is explicit and immutable. Its acquisition and extraction modes remain independent, while its load intent is either preview or apply so preview cannot request post-write work. Expected operational failures return `COMPLETED`, `PARTIAL`, or `FAILED`; invalid requests fail before side effects, and unexpected programming failures propagate. Existing per-source persistence transactions remain authoritative, so a failed import may truthfully report prior committed work. Cleanup failure after a completed write is a warning rather than a retryable import failure.
